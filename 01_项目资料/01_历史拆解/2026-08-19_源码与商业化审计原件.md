# Labas 中文化与变现改造审计

审计日期：2026-08-19  
对象：
- GitHub 仓库：https://github.com/rogasper/labas-bahasa
- 线上页面：https://labas.rogasper.com/bank

## 结论

这个项目不是只有线上成品，公开仓库里有完整源码。它是 Bun + Turborepo monorepo，包含 React/Vite 前端、Hono + tRPC 后端、PostgreSQL + Drizzle 数据层、Redis/BullMQ 后台任务、Better Auth 登录、管理员面板、AI 生成题目、题库、练习包、答题记录、排行榜、公告与免费额度池。

可以改成中文语言学习/备考产品，但商业化不能只靠翻译文案。现有 credit system 是“平台免费 AI token 池”，不是订阅、支付或会员权限。要变成可收费产品，需要补上订阅/订单/支付回调/权益判定/paywall UI 这条闭环。

最现实的路线是 fork 源码，先做“中文单语言商业版”，不要试图反编译线上打包产物。线上 `/bank` 只返回 SPA HTML，真实代码在 `/assets/*.js`，但源码仓库已经完整，没必要走逆向路线。

## 可用源码与构建产物

仓库可用内容：
- `apps/web`：React 19 + Vite + TanStack Router 前端。
- `apps/server`：Hono 服务入口，挂载 Better Auth 与 tRPC。
- `packages/api`：tRPC 业务路由，包括 AI 生成、题库、练习、管理员、公告、反馈、排行榜、Blog 等。
- `packages/db`：Drizzle schema、迁移、seed、Docker Compose。
- `packages/auth`：Better Auth 配置。
- `packages/ai`：OpenAI-compatible 题目生成 pipeline、prompt、schema、CPNS 专用 prompt。
- `packages/ui`：shadcn/ui 组件。
- `deploy`：Coolify 部署文档和 Nixpacks 配置。

线上可见构建形态：
- `https://labas.rogasper.com/bank` 返回 Vite SPA HTML。
- 页面语言标记为 `lang="id"`。
- 主资源是 `/assets/index-*.js`、`/assets/index-*.css`。
- 生产环境注入了 Rogasper 的 Umami 统计脚本。

关键技术栈：
- Runtime/package manager：Bun 1.3+
- Frontend：React + Vite + TanStack Router
- Backend：Hono + tRPC
- DB：PostgreSQL + Drizzle
- Queue：Redis + BullMQ
- Auth：Better Auth
- AI：OpenAI-compatible API

## 中文化可行性

可行，但不是低成本“一键 i18n”。

现状：
- 前端大量印尼语文案直接硬编码在组件里，没有看到成熟 i18n 层。
- `site-seo.ts`、`index.html`、`sitemap.xml`、`robots.txt`、OG/Twitter meta 都绑定 `labas.rogasper.com` 与 `id_ID`。
- 数据库 seed 里包含 IELTS、TOEFL、JLPT、HSK、Goethe、TOPIK、TOAFL、DELE、CPNS。
- AI prompt 默认说明为外语考试平台，部分 CPNS prompt 是印尼语专用。
- Auth 登录页有中文化入口价值，但目前 Better Auth 配置里 `disableSignUp: true`，公开注册被关闭。

建议：
- MVP 阶段先做单语言中文，不急着上完整多语言 i18n。
- 把品牌从 Labas 改成中文品牌，例如“语测工坊 / 语言备考实验室 / AI 题库训练营”，品牌名待定。
- 保留 IELTS/TOEFL/JLPT/HSK/TOPIK/DELE/Goethe；删除或隐藏 CPNS、TOAFL 可视目标取决于市场定位。
- 所有 SEO、OG、站点 URL、邮箱、社媒、统计脚本全部换成自己的。
- 把“用户自带 Key”从主路径降级为高级设置，商业版主路径应该是平台提供 AI 额度并收费。

## 应删除或替换的无关内容

必须删除/替换：
- Rogasper 品牌链接：`rogasper.com`、`admin@rogasper.com`、`instagram.com/rogasper`、GitHub rogasper 仓库链接。
- 捐赠模式：Saweria、Ko-fi、DonationModal、README Support。
- 社群模式：WhatsApp、Discord、Rogasper Learning、CommunityModal、CommunityCard。
- Rogasper Blog API：`BLOG_API_URL=https://api.rogasper.com`、`packages/api/src/routers/blog.ts`。
- Rogasper Umami 统计：`umami-analytic.rogasper.com` 与 website id。
- CPNS/Kedinasan 模块：`/cpns/*` 路由、`cpns-constants.ts`、CPNS prompt、CPNS seed、sidebar mode switcher。
- README/PRD 中“open-source/community/support creator”话术，改成商业产品说明。

高风险遗留：
- 如果 CPNS 不删，产品定位会混乱：语言学习用户会看到印尼公考模块。
- 如果仍保留 Saweria/Ko-fi，商业收款逻辑会显得像个人捐赠项目，不像可订阅产品。
- 如果不替换 Umami，流量数据会继续打到原作者的统计账户。

## 商业化现状

已有地基：
- `user.role`、`user.suspended` 已有管理员权限与封禁能力。
- `user_credit`、`credit_transaction` 已有 token 余额和交易记录。
- `platform_config` 可由管理员控制免费额度池、平台 AI key、公告。
- AI 生成入口已经会检查用户是否被封禁、免费额度是否开启、余额是否足够、每日 token budget。
- 管理员面板已有用户管理、额度管理、Featured 内容、公告、AI 配置、作业监控。

缺失闭环：
- 没有 `subscription` 表。
- 没有 `plan` / `price` / `entitlement` 表。
- 没有支付 provider customer id、checkout session、invoice、payment event 表。
- 没有 Stripe/Paddle/Creem/Lemon Squeezy 等支付依赖。
- 没有支付 webhook 验签。
- 没有“订阅状态 -> 权益 -> 额度补给 -> API 拦截”的服务端统一函数。
- 没有前端 Pricing 页面、Upgrade 弹窗、Billing Portal、套餐对比。

## 推荐变现模型

MVP 推荐三档：

免费试用：
- 注册后赠送固定额度，例如 20,000 token 或 5 次生成。
- 可做 1-2 套公开练习包。
- 不允许批量生成，不允许私有题库大量保存。

Pro 月付：
- 每月固定 AI token 包，例如 1,000,000 token。
- 无限练习公开题包。
- 私有题库、错题复盘、AI 解释、成绩趋势。

Creator/Admin：
- 更高额度。
- 可创建公开售卖题包。
- 内容审核、精选推荐、题包上下架、用户管理。

转化逻辑：
- 免费额度只用于体验“AI 生成题 + 做题反馈”的爽点。
- 到达上限后不要只报错，要弹出 Upgrade。
- 付费不是买“AI token”，而是买“备考效率”：智能生成、真题风格、错题复盘、专项训练、进度分析。

## 推荐实现路径

第一阶段：产品清洗与中文化
- 删除/隐藏 CPNS 和 Kedinasan mode。
- 删除 DonationModal、CommunityModal、CommunityCard、Rogasper 外链。
- 替换 SEO、站点名、OG 图、favicon、sitemap、统计脚本。
- 中文化 Landing、Login、Sidebar、Dashboard、Generate、Bank、Package、Attempt、Analytics、Admin。
- 将 seed 中 section name 改为中文展示名，或前端统一映射中文名。

第二阶段：权限与试用
- 新增 `plans`、`subscriptions`、`usage_periods`、`entitlement_events`。
- 新增 `getEntitlement(userId)`。
- 在 `ai.generate`、`package.create`、`attempt.start` 等关键接口加入服务端权益检查。
- 免费用户达到上限时返回结构化错误，例如 `PAYWALL_REQUIRED`。
- 前端捕获该错误，打开 Upgrade 弹窗。

第三阶段：支付
- 接入 Stripe Checkout Subscription。
- 新增后端 `billing.createCheckoutSession`、`billing.createPortalSession`、`billing.mySubscription`。
- 新增 `/api/webhooks/stripe`，处理 `checkout.session.completed`、`invoice.paid`、`customer.subscription.updated`、`customer.subscription.deleted`。
- Webhook 成功后更新本地订阅状态和月度额度。
- Secret key、webhook secret 只放后端环境变量。

第四阶段：内容与运营控制
- 把 Featured 内容升级为运营位：推荐题包、首页展示、限免题包、付费题包。
- 管理员增加套餐配置、用户订阅状态、手动赠送会员/额度。
- 增加基础收入指标：MRR、试用转化率、额度消耗、生成成功率。

## 法律与授权风险

仓库 license 是 AGPL-3.0。AGPL 允许商业使用，但如果你运行修改版网络服务，通常需要向该服务用户提供对应修改源码。这个点不要轻飘飘绕过去，尤其是你想做“我的闭源商业网站”时。可选路线：

- 接受 AGPL：公开你修改后的源码，但商业化服务、内容、品牌、数据、运营仍然可以收费。
- 找原作者谈商业授权/双授权：用钱换闭源权利。
- 重写核心代码：参考产品思路，不复用 AGPL 源码，成本高但商业控制权最干净。

这不是正式法律意见，上线前建议找懂开源许可证的律师确认。

## 建议优先级

我建议不要先“整体重写”。当前源码已经有非常多能复用的后端资产，最省钱路线是 fork 后做商业化收敛：

1. 先删 CPNS、社群、捐赠、Rogasper 品牌。
2. 做中文单语言版本。
3. 用现有 credit system 改出免费试用。
4. 再接订阅支付。
5. 最后优化内容运营与增长。

真正的死锁只有两个：AGPL 是否能接受，以及支付方式选什么。前者决定能不能闭源，后者决定技术接入和收款地区。
